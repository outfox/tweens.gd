## Compared with Godot's Tween

The same move, written with Godot's built-in `Tween` and with tweens.gd. The
tweens.gd version is shorter to type, and it reads in the order you think about
motion: what moves, where to, how long, and how it eases.

<Lang only="csharp">

<Variants labels={['One sprite', 'Three sprites']}>

<Compare>

```csharp title="Godot's Tween"
var target = new Vector2(400, 180);
var tween = sprite.CreateTween();
tween.TweenProperty(sprite, "position", target, 0.6)
    .SetTrans(Tween.TransitionType.Cubic)
    .SetEase(Tween.EaseType.Out);

await ToSignal(tween, Tween.SignalName.Finished);
GD.Print("Arrived");
```

```csharp title="tweens.gd"
var target = new Vector2(400, 180);
var movement = sprite.TweenPosition(target, 0.6,
    options => options.Ease = EaseType.CubicOut);

await movement;
GD.Print("Arrived");
```

</Compare>

<Compare>

```csharp title="Godot's Tween"
var target = new Vector2(400, 180);

var tween1 = sprite1.CreateTween();
tween1.TweenProperty(sprite1, "position", target, 0.6)
    .SetTrans(Tween.TransitionType.Cubic)
    .SetEase(Tween.EaseType.Out);

var tween2 = sprite2.CreateTween();
tween2.TweenProperty(sprite2, "position", target, 0.8)
    .SetTrans(Tween.TransitionType.Cubic)
    .SetEase(Tween.EaseType.Out);

var tween3 = sprite3.CreateTween();
tween3.TweenProperty(sprite3, "position", target, 1.0)
    .SetTrans(Tween.TransitionType.Cubic)
    .SetEase(Tween.EaseType.Out);

await ToSignal(tween3, Tween.SignalName.Finished);
GD.Print("Arrived");
```

```csharp title="tweens.gd"
var arrive = new Tweens.Position2D(new Vector2(400, 180), 0.6, EaseType.CubicOut);

_ = sprite1.Tween(arrive);
_ = sprite2.Tween(arrive with { Duration = 0.8 });
await sprite3.Tween(arrive with { Duration = 1.0 });
GD.Print("Arrived");
```

</Compare>

</Variants>

|  | Godot's Tween | tweens.gd |
| --- | --- | --- |
| Code | `CreateTween()`, a `TweenProperty()` step, then `SetTrans()` and `SetEase()` | One shorthand call, such as `sprite.TweenPosition(to, 0.6)` |
| Property | A string path and a `Variant`; mistakes surface at runtime | A typed method; the compiler checks the property and value |
| Easing | A `TransitionType` plus an `EaseType` | One `EaseType`, such as `CubicOut` |
| Reuse | Build a new `Tween` for each node and each replay | [Store a definition](/csharp/definitions/) and start it on any node; `with` varies one start |
| Variants | Copy the tween code and change its numbers | [Scale a shared definition](/csharp/variations/), as in `Recoil with { FactorBy = 2 }`; the variant follows later tuning |
| Ending | `Finished` fires on completion only | `End` settles with a `Reason`: completed, cancelled, owner left the tree |

</Lang>

## Three ways to write a tween

tweens.gd keeps tween code short with three layers that mix freely. Start with the
shortest one that fits, and move to the next when a motion grows.

<Lang only="csharp">

### Shorthand methods

Every property in the [catalog](/csharp/nodes/) has a shorthand method that starts
a tween in one call:

```csharp
await sprite.TweenPosition(new Vector2(400, 180), 0.6);
```

### Configurators

A configure callback adjusts one call. A shared `TweenOptions` value gives several
calls the same timing and easing:

```csharp
_ = sprite.TweenScale(Vector2.One, 0.25, options => options.From = Vector2.Zero);

var snappy = new TweenOptions { Duration = 0.25, Ease = EaseType.BackOut };
_ = label.TweenModulateAlpha(1, 0.25, snappy);
```

### Definitions

For motion you reuse, a definition gives it a name. It's a small struct that you
start on any node and vary with `with`:

<Moves>

```csharp {"1":1-6} {"2":8} {"3":9-10}
var arrive = new Tweens.Position2D
{
    To = new Vector2(400, 180),
    Duration = 0.6,
    Ease = EaseType.CubicOut,
};

var movement = sprite.Tween(arrive);
await movement;
GD.Print("Arrived");
```

1. **Define** the motion. Property, endpoint, duration, and easing sit together
   and read top to bottom.
2. **Start** it on a node. It begins wherever the node is and returns a handle.
3. **Await** the handle before continuing. [Check the result](/csharp/cancellation/)
   when your next action depends on successful completion.

</Moves>

</Lang>

<Lang only="gdscript">

### Named helpers

Every property in the [helper catalog](/gdscript/nodes/) has a helper that builds
its tween in one call:

```gdscript
await Tweens.play(sprite, Tweens.position_2d(Vector2(400, 180), 0.6)).end
```

### Decorators

Each `with_*()` method returns a copy with one setting changed, so a start can
adjust a helper or a shared definition in place. They chain:

```gdscript
var pop := Tweens.scale_2d(Vector2.ONE, 0.25, Tweens.Ease.BACK_OUT)
Tweens.play(sprite, pop.with_from(Vector2.ZERO).with_delay(0.1))
```

### Definitions

Every helper returns a definition. Keep one in a `static var`, and any node can
start it:

<Moves>

```gdscript {"1":1} {"2":3} {"3":4}
var arrive := Tweens.position_2d(Vector2(400, 180), 0.6, Tweens.Ease.CUBIC_OUT)

await Tweens.play(sprite, arrive).end
print("Arrived")
```

1. **Define** the motion. The helper names the property and checks the node's
   class; its arguments are the endpoint, duration, and easing.
2. **Start** it on a node and **await** its `end`. It begins wherever the node is.
3. **Continue** once it ends. [Check the result](/gdscript/cancellation/) when
   your next action depends on successful completion.

</Moves>

</Lang>
