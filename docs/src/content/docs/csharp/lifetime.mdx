A node owns the tweens started on it. When the node leaves the scene tree, its
tweens stop by themselves, so you rarely need cleanup code.

## Target and owner

The **target** receives values, and the **owner** decides when playback stops. For
a node tween, the node is both. Resource tweens, such as material tweens, bind to a
separate owner or to the scene tree.

## Nodes

Start node tweens from `_Ready` or later, while the node is inside the tree.

- Leaving the tree cancels the node's tweens at once, including removal and
  reparenting that exits the tree.
- A freed or queued-for-deletion target is never written again.
- Freeing an owner still finishes `End`, even while its tween is paused.

`node.CancelTweens()` cancels the tweens a node owns, and `includeChildren: true`
extends that to its descendants. It doesn't reach manual schedulers you created
yourself.

## Pausing

With the default pause mode, a tween pauses when its owner stops processing:

| `TweenPauseMode` | With an owner | Without an owner, bound to a tree |
| --- | --- | --- |
| `Bound` (default) | Follow `owner.CanProcess()` | Follow tree pause |
| `SceneTree` | Follow tree pause only | Follow tree pause |
| `Always` | Ignore owner and tree pause | Ignore tree pause |

Pausing the handle always stops it, even with `Always`. A node's
`SetProcess(false)` doesn't pause its tweens, because `CanProcess()` depends on
the node's `ProcessMode` and the tree's pause state.

## Resources

Animating a material changes the resource itself, so every node sharing it sees
the change. Playback never duplicates, reassigns, or disposes your resource.

Give a resource tween an owner to stop it when that node leaves the tree. A tween
scoped only to the tree keeps running when a mesh is removed or gets a new
material, because it still targets the original resource. Tree teardown stops
it. See [material lifetimes](/csharp/materials/#choose-the-playback-lifetime).

## How playback ends

Completion, cancellation, owner exit, target destruction, and runner teardown all
finish `End` with a [reason](/csharp/playback/#why-it-ended). Cancelling isn't an
error, so awaiting `End` returns `Reason.Cancelled` instead of throwing. A failure
in interpolation, easing, a setter, or a callback faults the tween.
`SuppressCallbacksWhenTargetInvalid` skips callbacks for an invalid target while
still finishing `End` and releasing bindings.

Handles keep their `Target` for inspection, so drop handles you no longer need.
Create and control tweens on Godot's main thread. A manual scheduler belongs to
the thread that created it, and native targets still need the main thread.
