Supply your own easing when a built-in family does not fit. It maps normalized progress to an interpolation weight.

Examples use `using Godot;` and `using tweens.gd;` in a Node method, with targets inside the scene tree.

## Use a function

```csharp
var move = new Tweens.Position2DX(300, 0.6)
{
    EaseFunction = t => t * t,
};

sprite.Tween(move);
```

This starts slowly and accelerates. At halfway through the time, the weight is 0.25, so the sprite has travelled a quarter of the distance.

<Aside type="tip" title="Time in, weight out">

Progress runs from 0 to 1. Return 0 at the start and 1 at the end for an ordinary arrival. Weights outside that range create overshoot; a function ending at 0 returns to its starting value.

</Aside>

## Use a Godot Curve

Create a `Curve` resource in the Inspector and shape its points over the 0–1 domain. Export a field to assign it:

```csharp title="CurveMotion.cs"
public partial class CurveMotion : Sprite2D
{
    [Export] public Curve MotionCurve { get; set; } = new();

    public override void _Ready()
    {
        var move = new Tweens.Position2DX(300, 0.6) { Curve = MotionCurve };
        this.Tween(move);
    }
}
```

Each playback gets its own curve copy, so edits affect later starts.

<Aside type="caution" title="Choose one custom source">

Set `EaseFunction` or `Curve`, not both. Either overrides the built-in ease. Custom profiles keep their own pacing instead of using the In/Out split controls.

</Aside>

Use the [playground](/easings/) for built-in families, [Effects](/csharp/effects/) for punch and shake, or the [easing reference](/csharp/api/easing/) for sampling details.
