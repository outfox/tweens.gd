Games rarely need a motion in just one version. A heavy hit kicks harder than a
light one, and an enemy that spawns pops in from nothing. Instead of copying a
definition and editing its numbers, start a variant of it. The variant stays
tied to the definition, so when you tune the definition, every variant follows.

Examples assume `using Godot;` and `using tweens.gd;`, and run on Godot's main
thread.

## A complete example

An enemy recoils when hit, harder and longer for more damage:

<Moves>

```csharp title="Enemy.cs" {"1":3-9} {"2":11-15} {"3":17}
public partial class Enemy : Sprite2D
{
    static readonly Tweens.Position2DX Recoil = new()
    {
        By = -12,
        Duration = 0.2,
        Ease = EaseType.QuadOut,
        UsePingPong = true,
    };

    public void Hit(float damage) => this.Tween(Recoil with
    {
        FactorBy = damage / 10,
        FactorDuration = 1 + damage / 100,
    });

    public void Crit() => this.Tween(Recoil with { FactorBy = 3, Skew = 0.5, Weks = 0.5 });
}
```

1. **Define the motion once.** `Recoil` kicks the enemy 12 pixels back and
   returns.
2. **Scale it per hit.** `FactorBy` scales the kick with the damage, and
   `FactorDuration` stretches the timing. A 20-damage hit kicks 24 pixels and
   takes 0.24 seconds each way.
3. **Change the pacing.** `Skew = 0.5` front-loads the same ease, so a critical
   hit lands sooner. `Weks = 0.5` keeps it near the far endpoint longer before returning.

</Moves>

Change `Recoil` to kick 16 pixels, or to ease with `CubicOut`, and every hit and
crit follows. `Recoil with { By = -24 }` would also kick harder, but it replaces
the value, so that variant no longer follows `Recoil`.

Try it below. Each row starts one variant with its own sliders: **Hit** scales
with the damage, and **Crit** uses its own factor. Each start has separate outward
and return pacing controls. The curve and code
show the row you used last. **Recoil kick** and **Recoil duration** tune the shared
definition, and both variants follow.

## Factors and deltas

When a tween starts, each factor multiplies its value and each delta is added
after it:

| Value | Becomes | Defaults |
| --- | --- | --- |
| `From` | `FactorFrom` × `From` + `DeltaFrom` | `1`, none |
| `To` | `FactorTo` × `To` + `DeltaTo` | `1`, none |
| `By` | `FactorBy` × `By` + `DeltaBy` | `1`, none |
| `Duration` | `FactorDuration` × `Duration` + `DeltaDuration` | `1`, `0` |
| `Delay` | `FactorDelay` × `Delay` + `DeltaDelay` | `1`, `0` |

Deltas have the definition's value type, such as `Vector2` for a position.
The duration and delay factors and deltas are timing options, so a shared
`TweenOptions` can carry them: `options with { FactorDuration = 1.5 }`.
`DeltaDelay` suits a stagger: `Pop with { DeltaDelay = i * 0.1 }` keeps `Pop`'s
own delay and adds each item's offset to it.

## Vary the current value

An omitted `From` or `To` is read from the property when the tween starts. A
factor or delta then makes the motion relative to wherever the property is:

```csharp title="Heart.cs"
public partial class Heart : Sprite2D
{
    static readonly Tweens.Scale2D Beat = new()
    {
        FactorTo = 1.2,
        Duration = 0.15,
        Ease = EaseType.SmootherStep,
        UsePingPong = true,
    };

    public void Pulse() => this.Tween(Beat);
}
```

The heart grows to 120% of whatever scale it has and comes back.

- `FactorFrom = 0` grows from zero to the current value.
- `DeltaFrom = new Vector2(0, 40)` on a position starts 40 pixels lower and
  rises to where the node is.
- `DeltaTo` works like `By`, but only once: it's computed when the tween starts,
  while `By` keeps up with other changes to the property as it plays.

## Change the pacing with `Skew`

`Skew` reshapes when the motion happens without choosing another ease. Normalized
time `t` becomes `t` to the power of `Skew` before the ease sees it:

- `Skew` above 1 rear-loads the ease: the motion starts slower and catches up.
  At a quarter of the duration, `Skew = 2` passes 0.0625 to the ease.
- `Skew` between 0 and 1 front-loads it: most of the motion happens early.
- The default, 1, leaves the ease unchanged.

```csharp
var movement = sprite.Tween(new Tweens.Position2D
{
    To = new Vector2(300, 120),
    Duration = 0.5,
    Ease = EaseType.CubicOut,
    Skew = 2,
    Weks = 0.5,
    UsePingPong = true,
});
```

`Skew` controls the outward leg; `Weks` controls the ping-pong return.
Both default independently to `1`. On return, raw progress `t` runs from
1 down to 0, and the ease receives `pow(t, Weks)`. For example, with
`Weks = 2`, halfway back the ease receives 0.25. Above 1 moves the return
earlier along the reversed curve; below 1 keeps it near the far endpoint longer.
`Weks` has no effect on forward-only tweens.

Both exponents apply to built-in eases, `EaseFunction`, and `Curve` samples.
Duration, intervals, and the handle's raw `Progress` stay unchanged. For
bounce, elastic, and other eases that aren't monotonic, the exponents shift when
their bounces and overshoot happen but keep them.

**Migration:** previously, `Skew` also shaped the return. Set
`Weks` equal to `Skew` to preserve that behavior and retrace the same
curve. Leave `Weks` at `1` for the unmodified return ease.

## Rules

- Factors and deltas apply once, when the tween starts. A non-retaining `Fill`
  restores the captured value, not an adjusted one.
- For a quaternion, the factor scales the rotation angle and the delta rotates
  about the node's own axes.
- `FactorBy` and `DeltaBy` need a `By`. `FactorTo` and `DeltaTo` don't apply to
  a `By` tween. Both combinations are rejected.
- Adjusting `From` fixes the start of a `By` tween, as an explicit `From` does.
- The adjusted duration and delay must not be negative, and `Offset` must fit
  within the adjusted duration.
- Factors, `DeltaDuration`, `DeltaDelay`, `Skew`, and `Weks` must be finite.
  Both exponents must be greater than zero, even without ping-pong. Invalid values reject the start.
