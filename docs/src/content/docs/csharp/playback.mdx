Every start returns a handle. Use it to pause, resume, or cancel playback, and
await the handle before continuing.

Snippets run in an async Node method with an in-tree `Sprite2D` named `sprite`,
and assume `using Godot;`, `using tweens.gd;`, and `using System;`.

## Pause, resume, cancel

<PlaybackRemote />

Handles are `TweenInstance<TTarget, TValue>`. Their non-generic `TweenInstance`
base lets you keep different tween types in one collection. Cancelling keeps the
latest value. To cancel every tween a node owns, call `node.CancelTweens()`.

## Await playback

```csharp
var movement = sprite.TweenPosition(new Vector2(400, 180), 0.6);
await movement;
```

Handles and groups are directly awaitable. You can ignore the returned reason;
keep it only when your next action depends on how playback ended. See
[cancellation and completion reasons](/csharp/cancellation/) for guarded sequences
and cancelling just one wait.

`await movement` uses the same shared `Task<Reason>` as `movement.End`, including
its faults. Any number of callers can await it, even after playback has ended.
Use `End` when another API needs a task. Direct awaiting uses `GetAwaiter()`;
there is no implicit conversion to `Task`.

Starting an awaitable tween without waiting is still supported. In an async method,
write `_ = sprite.TweenPosition(new Vector2(400, 180), 0.6);` to explicitly discard
the handle and avoid C#'s unawaited-call warning.

## Callbacks

Definitions accept typed callbacks. They run in this order:

1. `OnAdd` when the tween is added.
2. `OnUpdate` with `From`, only when the fill mode applies it during the delay.
3. `OnStart` once, when playback begins.
4. `OnUpdate` once per eligible frame with the sampled value, plus once more when
   completion restores the initial value.
5. `OnEnd` on natural completion, or `OnCancel` when playback stops early.
6. `OnFinally` in every case, including faults.

The handle's terminal state is visible before terminal callbacks run, and each
terminal callback runs at most once. A long frame doesn't replay the callbacks
of skipped cycles. Tweens created in `OnUpdate` begin on the next update, while
tweens created in `OnEnd` continue the finished tween's timeline exactly.

## Errors

An exception in interpolation, easing, a setter, or a callback faults the tween.
`End` throws when awaited, `Error` holds the exception, and several failures are
kept in an `AggregateException`. Cleanup and `OnFinally` still run, and other
tweens keep playing. Schedulers also report the error through
`UnhandledException`, and the automatic runner forwards it to `GD.PushError`.

:::caution[Catch errors in `async void` callbacks]
`_Ready` and other Godot callbacks are often `async void`. Wrap their sequences in
`try`/`catch`, or a faulted tween's exception is lost.
:::

## Stay on the main thread

Create and control tweens, and await `End`, on Godot's main thread. `End` finishes
there, and ordinary Godot async code keeps its synchronization context.

- Don't block with `.Wait()` or `.Result`.
- Don't use `Task.Run` or `ConfigureAwait(false)` around engine access.
- Use Godot's `ToSignal` to wait for unrelated engine signals; tweens.gd has no
  coroutine API.
