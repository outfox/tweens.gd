tweens.gd ships C# and GDScript source together in one Godot addon. Copy the addon
into your Godot .NET project and build normally. NuGet is an optional route for
experienced C# users.

:::note[Beta]
The C# API may change during beta.
:::

You need .NET 10 and a Godot .NET engine that matches GodotSharp 4.7.2; your game
supplies the engine. [Compatibility](/compatibility/) lists what has been
validated. The package ID and the namespace are both lowercase `tweens.gd`.

## Add the library

The addon is the default route. Use one C# implementation in a project.

<Tabs>
<TabItem label="Godot addon">

Copy `addons/tweens_gd/` from the repository, or unpack the unified release ZIP
into your project root. The C# sources live in `addons/tweens_gd/csharp/` and are
included by the project's normal build. Keep `Generated/`: it contains the
prepared definitions, so there is no tweens.gd analyzer to install or run.
Godot's own source generators run normally through your Godot.NET.Sdk.

Set your project's target framework to `net10.0` if needed. No plugin activation,
autoload or package reference is required. Both languages can coexist; GDScript
uses its own runtime and entry script.

The package is prepared for the [Godot Asset Store](https://store.godotengine.org/).
Until a public version is available, use a repository checkout or build the ZIP:

```powershell
./scripts/Pack-Addon.ps1
```

This writes `artifacts/packages/tweens.gd-0.1.0-pre.zip`.

</TabItem>
<TabItem label="Project reference">

For library development, clone the repository and reference its project from
your game's project, adjusting both paths:

```powershell
dotnet add path/to/YourGame.csproj reference path/to/tweens.gd/csharp/tweens.gd.csproj
```

Godot then builds the library together with your game.

</TabItem>
<TabItem label="Local NuGet package">

<Steps>

1. From the repository root, pack the library. This writes
   `tweens.gd.0.1.0-pre.nupkg` and a symbol package:

   ```powershell
   dotnet pack csharp/tweens.gd.csproj -c Release -o artifacts/packages
   ```

2. In your game's `NuGet.config`, add the absolute path of that directory next to
   nuget.org, which supplies GodotSharp:

   ```xml
   <configuration>
     <packageSources>
       <clear />
       <add key="local-tweens" value="C:/path/to/tweens.gd/artifacts/packages" />
       <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
     </packageSources>
   </configuration>
   ```

3. Reference the package in your game's project file, then run `dotnet restore`:

   ```xml
   <ItemGroup>
     <PackageReference Include="tweens.gd" Version="0.1.0-pre" />
   </ItemGroup>
   ```

</Steps>

</TabItem>
</Tabs>

If using NuGet or a project reference while keeping the addon for GDScript,
exclude the bundled C# sources in your game's project file to avoid duplicate
types:

```xml
<ItemGroup>
  <Compile Remove="addons/tweens_gd/csharp/**/*.cs" />
</ItemGroup>
```

Alternatively, omit the addon's `csharp/` directory. NuGet contains the compiled
C# API and needs no tweens.gd analyzer at the consumer end either.

Then write [your first tween](/csharp/quickstart/).
