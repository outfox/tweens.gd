A definition describes motion. Each start copies its settings into independent playback, so one definition can animate many nodes.

Examples use the global `Tweens` class in a node script, with targets inside the scene tree.

## Define once, start twice

```gdscript
var nudge := Tweens.position_2d()
nudge.by_value = [80, 0]
nudge.duration = 0.2
nudge.ease = Out.CUBIC

Tweens.play(sprite1, nudge)
Tweens.play(sprite2, nudge)
```

Both sprites move 80 pixels right from their own positions. Each start returns its own handle.

<Aside type="tip" title="Keep reusable motion nearby">

Store a shared definition in a `static var`. Treat it as read-only and use `with_*()` copies for individual starts.

</Aside>

## Choose the endpoints

| Choose | Result |
| --- | --- |
| `to_value` | Move to a destination |
| `from_value` only | Animate an entrance to the value set in the scene |
| `by_value` only | Add an offset, preserving other movement |

An omitted endpoint uses the property's value when playback starts, before any delay.

<Aside type="note" title="Relative motion">

Use `to_value` or `by_value`, not both. Leave `from_value` out when an offset should add to other movement.

</Aside>

## Vary one start

```gdscript
Tweens.play(sprite2, nudge.with_duration(0.6))
```

The copy takes longer; the original still takes 0.2 seconds. Already running tweens keep their settings.

**Try it:** change the second duration and play both.
