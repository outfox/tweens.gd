Games rarely need a motion in just one version. A heavy hit kicks harder than a
light one, and an enemy that spawns pops in from nothing. Instead of copying a
definition and editing its numbers, start a variant of it. The variant stays
tied to the definition, so when you tune the definition, every variant follows.

Examples assume the global `Tweens` class and
run on Godot's main thread, on nodes inside the tree.

## A complete example

An enemy recoils when hit, harder and longer for more damage:

<Moves>

```gdscript title="enemy.gd" {"1":3-4} {"2":6-8} {"3":10-11}
extends Sprite2D

static var recoil := Tweens.position_2d_x(null, 0.2, Out.QUAD) \
	.with_by(-12.0).with_ping_pong()

func hit(damage: float) -> void:
	Tweens.play(self, recoil.with_factor_by(damage / 10.0) \
		.with_factor_duration(1.0 + damage / 100.0))

func crit() -> void:
	Tweens.play(self, recoil.with_factor_by(3.0).with_skew(0.5).with_weks(0.5))
```

1. **Define the motion once.** `recoil` kicks the enemy 12 pixels back and
   returns.
2. **Scale it per hit.** `with_factor_by()` scales the kick with the damage, and
   `with_factor_duration()` stretches the timing. A 20-damage hit kicks 24 pixels
   and takes 0.24 seconds each way.
3. **Change the pacing.** `with_skew(0.5)` front-loads the same ease, so a
   critical hit lands sooner. `with_weks(0.5)` keeps it near the far endpoint longer before returning.

</Moves>

Change `recoil` to kick 16 pixels, or to ease with `CUBIC_OUT`, and every hit and
crit follows. `recoil.with_by(-24.0)` would also kick harder, but it replaces the
value, so that variant no longer follows `recoil`.

Try it below. Each row starts one variant with its own sliders: **Hit** scales
with the damage, and **Crit** uses its own factor. Each start has separate outward
and return pacing controls. The curve and code
show the row you used last. **Recoil kick** and **Recoil duration** tune the shared
definition, and both variants follow.

## Factors and deltas

When a tween starts, each factor multiplies its value and each delta is added
after it:

| Value | Becomes | Defaults |
| --- | --- | --- |
| `from_value` | `factor_from` × `from_value` + `delta_from` | `1.0`, `null` |
| `to_value` | `factor_to` × `to_value` + `delta_to` | `1.0`, `null` |
| `by_value` | `factor_by` × `by_value` + `delta_by` | `1.0`, `null` |
| `duration` | `factor_duration` × `duration` + `delta_duration` | `1.0`, `0.0` |
| `delay` | `factor_delay` × `delay` + `delta_delay` | `1.0`, `0.0` |

Deltas have the property's value type, such as `Vector2` for a position; `null`
adds nothing. Each field has a `with_*()` method, such as `with_factor_to()` or
`with_delta_duration()`. `delta_delay` suits a stagger:
`pop.with_delta_delay(i * 0.1)` keeps `pop`'s own delay and adds each item's
offset to it.

## Vary the current value

A `null` `from_value` or `to_value` is read from the property when the tween
starts. A factor or delta then makes the motion relative to wherever the property
is:

```gdscript title="heart.gd"
extends Sprite2D

static var beat := Tweens.scale_2d(null, 0.15, InOut.SMOOTHER_STEP) \
	.with_factor_to(1.2).with_ping_pong()

func pulse() -> void:
	Tweens.play(self, beat)
```

The heart grows to 120% of whatever scale it has and comes back.

- `with_factor_from(0.0)` grows from zero to the current value.
- `with_delta_from([0, 40])` on a position starts 40 pixels lower and
  rises to where the node is.
- `delta_to` works like `by_value`, but only once: it's computed when the tween
  starts, while `by_value` keeps up with other changes to the property as it
  plays.

## Change the pacing with `skew`

`skew` reshapes when the motion happens without choosing another ease. Normalized
time `t` becomes `pow(t, skew)` before the ease sees it:

- `skew` above 1 rear-loads the ease: the motion starts slower and catches up.
  At a quarter of the duration, a skew of `2.0` passes 0.0625 to the ease.
- `skew` between 0 and 1 front-loads it: most of the motion happens early.
- The default, `1.0`, leaves the ease unchanged.

```gdscript
var movement := Tweens.position_2d([300, 120], 0.5, Out.CUBIC)
Tweens.play(sprite, movement.with_ping_pong().with_skew(2.0).with_weks(0.5))
```

`skew` controls the outward leg; `weks` controls the ping-pong return.
Both default independently to `1.0`. On return, raw progress `t` runs from
1 down to 0, and the ease receives `pow(t, weks)`. For example, with
`weks = 2`, halfway back the ease receives 0.25. Above 1 moves the return
earlier along the reversed curve; below 1 keeps it near the far endpoint longer.
`weks` has no effect on forward-only tweens.

Both exponents apply to built-in eases, `ease_function`, and `curve` samples.
Duration, intervals, and the handle's raw `progress` stay unchanged. For
bounce, elastic, and other eases that aren't monotonic, the exponents shift when
their bounces and overshoot happen but keep them.

**Migration:** previously, `skew` also shaped the return. Set
`weks` equal to `skew` to preserve that behavior and retrace the same
curve. Leave `weks` at `1.0` for the unmodified return ease.

## Rules

- Factors and deltas apply once, when the tween starts. A non-retaining `fill`
  restores the captured value, not an adjusted one.
- For a quaternion, the factor scales the rotation angle and the delta rotates
  about the node's own axes.
- `factor_by` and `delta_by` need a `by_value`. `factor_to` and `delta_to` don't
  apply with `by_value`. Both combinations are rejected.
- Adjusting `from_value` fixes the start of a `by_value` tween, as an explicit
  `from_value` does.
- The adjusted duration and delay must not be negative, and `offset` must fit
  within the adjusted duration.
- Factors, deltas, `skew`, and `weks` must be finite. Both exponents must be
  greater than zero, even without ping-pong. Invalid values reject the start.
