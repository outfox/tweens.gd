Every start returns a handle. Use it to pause, resume, or cancel playback, and
await its `end` before continuing.

Snippets run in a node script function with an in-tree `Sprite2D` named `sprite`,
and assume `const Tweens = preload("res://addons/tweens_gd/tweens.gd")`.

## Pause, resume, cancel

<PlaybackRemote lang="gdscript" />

Handles are `TweensGdHandle` objects. `is_paused` reports the pause state and
can be assigned too. Cancelling keeps the latest value. To cancel every tween a
node owns, call `Tweens.cancel_tweens(node)`; pass `true` as the second argument
to include descendants.

The handle also exposes `state`, `progress`, `value`, `target`, `is_terminal`,
`is_settled`, `completion_reason`, and `error`. `progress` is the position within
the current leg, and runs backwards on the return leg of a ping-pong.

## Await playback

```gdscript
var movement := Tweens.play(sprite, Tweens.position_2d(Vector2(400, 180), 0.6))
await movement.end
```

Handles and groups expose `end`. You can ignore the returned reason; keep it only
when your next action depends on how playback ended. See
[cancellation and completion reasons](/gdscript/cancellation/) for guarded sequences
and cancelling just one wait.

While running, `end` returns the handle's `ended(reason)` signal. Once settled,
it returns the stored reason immediately, including when a start was rejected.
GDScript's `await` handles both forms. Read and await the property in one expression;
don't cache the signal for later, because signals do not replay.

Use `ended.connect(callback)` for a signal subscription to a running tween.
Use `await movement.end` for a wait that also works after completion.
The existing `wait()` coroutine still works; `wait(token)` adds wait cancellation.

## Callbacks

Definitions accept Callables in these fields. They run synchronously, in this
order:

1. `on_add(handle)` when the tween is added.
2. `on_update(handle, value)` with `from_value`, only when the fill mode applies
   it during the delay.
3. `on_start(handle)` once, when playback begins.
4. `on_update(handle, value)` once per eligible frame with the sampled value,
   plus once more when completion restores the initial value.
5. `on_end(handle)` on natural completion, or `on_cancel(handle)` when playback
   stops early.
6. `on_finally(handle)` in every case, including failures.

The handle's terminal state is visible inside terminal callbacks, and awaiting `end`
resumes after them. A long frame doesn't replay the callbacks of skipped cycles.
Tweens created in `on_update` begin on the next update, while tweens created in
`on_end` continue the finished tween's timeline exactly.

:::caution[Don't `await` inside callbacks]
Callbacks must return before playback continues. Put anything that awaits in a
separate coroutine that awaits `end`.
:::

## Errors

GDScript has no exceptions to throw, so failures are reported as data. A tween
that detects a problem ends with `FAILED`, and `handle.error` holds the message;
several detected problems are joined with newlines. `on_finally` still runs, and
other tweens keep playing. The automatic runner also reports the message to
Godot's error log.

A rejected start, such as a freed target, a target outside the tree, or an
invalid definition, doesn't return `null`. It returns a handle that has already
settled with `FAILED`. It schedules no work and runs no callbacks, its `target`
and `value` are `null`, and `pause()`, `resume()`, `cancel()`, and `wait()` stay
safe to call.

:::caution[Script errors aren't caught]
tweens.gd detects invalid configuration, stale Callables, non-numeric or
non-finite easing, and non-finite interpolation. An error inside your own
callback or property setter stays an ordinary Godot script error, and isn't
guaranteed to become `FAILED`.
:::

## Stay on the main thread

Create and control tweens, and await `end`, on Godot's main thread. A call
from another thread reports an error and does nothing: starts return a handle
that has already failed, and `wait()` returns `FAILED`.
