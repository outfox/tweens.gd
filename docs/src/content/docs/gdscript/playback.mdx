Every start returns a handle. Keep it to control that playback, or await its end before continuing.

Examples use the global `Tweens` class in a node script, with targets inside the scene tree.

## Pause, resume, cancel

<PlaybackRemote lang="gdscript" />

Cancelling keeps the latest value. `Tweens.cancel_tweens(sprite)` cancels all playback owned by that node.

## Await playback

```gdscript
var movement := Tweens.play(sprite, Tweens.position_2d([400, 180], 0.6))
await movement.end
```

The wait finishes after callbacks and cleanup. It also resumes when playback is cancelled or its owner leaves the tree.

<Aside type="caution" title="Continue only after arrival">

If the next action needs success, check `await movement.end == Tweens.Reason.COMPLETED`. The [cancellation guide](/gdscript/cancellation/) shows a guarded sequence.

</Aside>

<Aside type="note" title="Await the property directly">

Use `await movement.end`, which also works after completion. Do not cache the `ended` signal for a later wait: signals do not replay.

</Aside>

## Callbacks

Use a callback for a small synchronous reaction:

```gdscript
var arrive := Tweens.position_2d([400, 180], 0.6, Out.CUBIC) \
    .with_on_end(func(_handle): print("Arrived"))
Tweens.play(sprite, arrive)
```

`on_end` runs on natural completion. `on_finally` also runs when playback stops early or fails. See [callback order](/gdscript/api/callbacks/#callback-order) for the full lifecycle.

## Errors

Detected failures return `Tweens.Reason.FAILED`; read `handle.error` for the message. Arbitrary errors inside your scripts remain Godot script errors.

<Aside type="caution" title="Use Godot’s main thread">

Create, control, and await tweens on the main thread. Keep callbacks synchronous; put code that awaits after `await handle.end`.

</Aside>
