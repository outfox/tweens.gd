Duration sets how long a motion takes; delay sets when it begins. Add ping-pong and repeats for idle motion that runs itself.

Examples use the global `Tweens` class in a node script, with targets inside the scene tree.

## Loop forever

```gdscript
var pulse := Tweens.scale_2d([1.1, 1.1], 0.8, InOut.SINE) \
    .with_ping_pong().with_repeats(Tweens.INFINITE)

Tweens.play(sprite, pulse)
```

The sprite grows for 0.8 seconds, shrinks for 0.8 seconds, and repeats until cancelled or removed from the tree.

## Count cycles

| Set | Result |
| --- | --- |
| `with_repeats(2)` | Three cycles: the first plus two repeats |
| `with_ping_pong()` | Each cycle goes forward, then back |
| `ping_pong_interval` | Wait at the far endpoint |
| `repeat_interval` | Wait between cycles |

**Try it:** add a return leg and drag the timeline to see where the intervals fit.

## Fill and restoration

The default keeps the final value. For an entrance with a delay, use `with_fill(Tweens.Fill.BOTH)` so the starting value is visible while waiting.

**Try it:** switch fill modes to compare waiting and completion.

<FillModes lang="gdscript" />

<Aside type="note" title="Cancellation keeps the current value">

Restoration applies on natural completion. Cancelling keeps the latest sample, regardless of fill mode.

</Aside>

## Process and physics

Playback uses process frames by default. Pass `Tweens.playback_options()` at the start for physics updates or unscaled time.

The [timing reference](/gdscript/api/timing/) lists every option, fill mode, and validation rule. [Playback modes](/gdscript/api/modes/) control the clock; [ownership](/gdscript/lifetime/) controls pausing with the scene.
